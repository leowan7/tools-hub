{# pilot_card.html — the named starter recipe for one tool. A "pilot" is a guided FIRST run on the user's OWN target, with the cost and the runtime stated before they commit. It formalises the "start with 4-8 designs, then scale" advice that was written as prose in five different meta.py files and implemented nowhere. It is NOT a promise of a discount. Three tools (boltzgen, esmfold2-design, iggm) bill a flat price with no cheaper configuration reachable from their form, so their pilot costs exactly what any run costs; their PILOT prose says so in as many words. The narration — goal, what you need, cost, next step — is the part that carries its weight for someone who does not yet know what to run first, and that is true whether or not the params dial anything down. The dict comes from ``tool_public_context(adapter).pilot``, built by ``blueprints/tools.py::_pilot_context``. meta.py declares only the words and the parameter set; the PRICE AND THE RUNTIME ARE DERIVED — the price from ``estimated_cost_for_tool`` over the same params the form itself posts to /api/wallet/estimate, the runtime from the existing preset runtime map. Nothing here may hard-code either: a second hand-written rate card drifts off the real one within a month. ``pilot`` is None for the fast predictors (esmfold, colabfold, af2), and this macro then renders nothing at all. WHY ``|safe`` ON THREE FIELDS AND NOT THE OTHERS. ``goal``, ``you_need`` and ``next_step`` are prose written by us in ``tools//meta.py`` and they contain markup on purpose — ``—`` on four tools, ``A1-150`` on proteina. Without the filter those render as literal ``&mdash;`` on a page that is now publicly indexable, which is what shipped. Every sibling explainer macro (about_panel, worked_example) already marks the same class of author-written prose safe, so this is the convention, not an exception. The provenance is what makes it safe, and it is worth stating: the whole dict is a module-level constant. ``_pilot_context`` builds it as ``dict(meta.PILOT, params=..., cost_usd=..., runtime=..., url=..., hotspot_help_url=...)`` — nothing from ``request`` is merged in at any point, and the slug that picks the module is already validated by ``_require_tool``. If a future field ever reads from the form or the query string, it does not get this filter.
